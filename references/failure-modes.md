# Failure Modes

整卷二次开发最容易卡住的九个点。卡住就查表，不许「先往下做，回头再说」。

## Contents

1. 识别与分段
2. 读取与输入
3. 体裁判定
4. 撰题与改编
5. 校验与交付

## 1. 识别与分段

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| `exam_sectionizer.py` 识别板块 < 4，或 `not_detected_ids` 非空 | 看 manifest 的 `detection_source`：`explicit` 则按 `structural_rules` 核对「第N部分／第N节／裸字母」后重跑；`structural` 则看原文是否根本不是高考体例 | 转人工分段：手填 manifest 的 `start` / `end`，QA 记 `manual_segment: true`，告知用户哪几段是人工切的 |
| 板块边界压到上一板块的题号区（末题选项被算进下一段） | 核对 manifest 的 `line` 与 `char_count`，把起点移到真正的板块标题行 | 手工修正后重跑校验，QA 记该处人工干预 |

## 2. 读取与输入

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 脚本退出码 2（读不了文件） | PDF 先转文本再喂；加密或损坏件先解密、让用户重导 | 明确告知「需要可抽取的文本」，停在这里，不猜内容 |
| 抽取后中文字符残缺、英文连成一片 | 换 OCR 或换抽取工具重跑一遍 | 仍残缺 → 只处理能确认的板块，其余在 QA 记「无法读取」 |
| 答案与题号对不上（多版本混排） | 按卷名、题号、篇首句、答案位置四重配对 | 配不上 → 不用该答案文件，改为人工核对并在 QA 标明 |

## 3. 体裁判定

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| `genre.confidence < 0.45` | 按 `genre-routing.md` 第 2 节四类线索重判，写进 `genre.confirmed` | 仍两可：按「承载主要考点的层次」定类并写理由；两边都成立就取不做 IV 的三层方案（少做不错） |
| 一篇同时像说明又像议论 | 看题目落点：多数题考信息就按说明，考论证手法或态度就按议论 | 题目本身混杂 → 取说明（IV-A 更稳），在 QA 写理由 |

## 4. 撰题与改编

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 某题的「辨／错／换」写不出来 | 换一道题，别硬凑 | 整个板块凑不出 → 该板块不开设，QA 记原因 |
| IV-A 改编空数 ≠ 8，或改编后事实链变形 | 重写改编段，事实顺序与原篇对齐 | 改两轮仍变形 → 删该 IV，只留三层，QA 记原因 |
| III 层原句在原文中找不到 | 回原卷逐字复制，补段落定位 | 原文印刷错误 → 照原样引用并注「原文如此」，不改写 |
| 词族关系说不通（形似但非同源） | 改标 `拓展`，按同义、反义或同形异义处理 | 说不清关系 → 不收该词，换一个 |

## 5. 校验与交付

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| `validate_packet.py` 退出码 1 | 按 `errors` 逐条回内容模型改，重新生成两版 | 修两轮仍 FAIL → 停止交付，把 `errors` 原文交给用户，不自行降级放行 |
| `check_registry.py` FAIL | 按报错改注册表或文档，标题一律以注册表为准 | 注册表本身设计有误 → 先改注册表再跑一次，不许绕过校验出稿 |
| 学生版仍检出泄漏但肉眼看不到 | 查页眉页脚、批注、隐藏文字、彩色字体四项，逐项定位 | 四项都干净仍报错 → 按 `student_leakage` 的匹配词回正文全文搜索 |
